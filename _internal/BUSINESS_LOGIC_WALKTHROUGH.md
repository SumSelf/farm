# 闪马田园 SUMFARM · 用户级业务逻辑走查与整改报告

> 当前交付规模：**166 页**（前台 145 + 后台 21），资源版本 `v1.7.8`，域名 `iarm.fun`。本文出现的 118 / 127 / 131 / 143 页等为对应整改轮次当时的历史值，不代表当前页面数。


> 视角：租户、田园/集体商家、接单农户、技术专家、平台管理员。
> 验收句式只用「用户做了 X → 得到 Y」；「元素存在」「无报错」只是前置条件，不算通过。
> 本轮不新增一级频道，只补齐每个使用者**天天会做、但原站没有**的常规动作。

## 一、走查结论（先说问题）

上一轮把五角色的**正向业务链**接通了（看田 → 承包 → 下单 → 派工 → 验收 → 结算），
但站在一个真实使用者的角度，平台还缺「做完一单之后怎么办」和「自己那一摊怎么管」：

| 使用者 | 常规动作 | 走查前 | 走查后 |
|---|---|---|---|
| 普通租户 | 取消工单、申请退款、看退款到哪一步 | **完全没有** | 取消 → 退款申请 → 退款进度，三步闭环 |
| 普通租户 | 改工单、按原工单重发、查改动留痕 | **完全没有** | 修改 → 变更记录；重新发起 → 新工单详情 |
| 田园/集体商家 | 改租赁信息、管合同、逐条改条款、比版本 | 只有一张合同页 | 租赁变更 → 合同管理 → 条款编辑 → 版本对比 |
| 田园/集体商家 | 对账、逐笔账单、某一期对账单 | **完全没有** | 对账中心 → 账单明细 → 对账单详情 |
| 田园/集体商家 | 发布活动、更新活动、看内容版本、看报名名单 | 只有报名/签到 | 活动管理 → 发布 / 更新 → 版本 → 报名名单 |
| 接单农户 | 看自己的钱、看流水、看结算单 | **完全没有** | 资金总览 → 资金流水 → 结算单 |
| 接单农户 | 提现、超额拦截、看到账进度 | **完全没有** | 申请提现（边界校验）→ 提现进度 |
| 技术专家 | 多维度统计、跨田块对比、按对比结果调控 | 只有积分/专栏 | 多维统计 → 数据对比 → 调控建议 → 调控记录 |
| 技术专家 | 按条件查种植记录、看单条读数与回执 | 只有后台台账 | 种植记录查询 → 记录详情 |
| 平台管理员 | 对退款、提现、合同版本、调控记录做管控 | 后台无对应台账 | 4 个独立管控页 + 审核动作 + 审计日志 |

**结论**：原站不是死链站点，但「用户级产品平台」的常规动作缺了一大半。本轮全部补齐。

## 三、逐按钮五问（关键新动作示例）

| 按钮 | 点了有什么可见反馈 | 是否符合点击意图 | 跳过去是不是用户要的 | 怎么返回 | 边界行为 |
|---|---|---|---|---|---|
| 取消工单 → 提交 | 表单换成「已取消 · 进入退款流程」成功态 + toast | 是：工单状态改变 | 下一步到退款申请，且带工单号 | 动作条可回工单总览，浏览器后退回来源页 | 已作业金额按公示价折算，不整单退；重复提交加锁 |
| 申请退款 → 提交 | 成功态写明「待平台核对」 | 是：生成退款单 | 下一步到退款进度四步时间线 | 第二按钮到变更记录 | 金额由订单 + 公示费率实时算，不写死 |
| 修改工单 → 提交 | 成功态写明「已修订 · 变更留痕」 | 是：范围/时间/验收/预算改动 | 下一步到变更记录 | 可点回原工单详情 | 必填缺失被拦；已被承接的工单不在这里改 |
| 重新发起 → 提交 | 成功态写明生成新工单号 | 是：按原单模板重发 | 下一步到新工单详情 | 旧单仍在变更记录 | `copyFrom` 显式参数，不依赖会话 |
| 编辑合同 → 保存 | 成功态写明新版本已生成 | 是：五类条款逐条改 | 下一步到版本对比 | 回合同管理 | 双方确认前不影响已生效合同 |
| 对账中心 → 切维度 | 统计卡与分组表整体换数 | 是：按账期/类型/状态重算 | 不跳页，原地换数据 | 维度 chip 可切回 | 数字由 24 条账单实时聚合 |
| 发布活动 → 提交 | 成功态写明已提交公示 | 是：活动进入公示与报名 | 下一步到活动管理 | 第二按钮到田园活动 | 必填校验；价格取自公示总账口径 |
| 申请提现 → 超额 | 页面不生成提现单，toast 写明原因 | 是：拦住错误金额 | 留在原页继续改 | 不改 URL | 低于 100 元、超过可提现余额都拦 |
| 申请提现 → 合法 | 成功态写明「待复核」 | 是：生成提现单 | 下一步到提现进度 | 第二按钮到资金流水 | 手续费与到账额提交前算给用户看 |
| 数据对比 → 换田块 | 并排表随 `?ids=` 重排，相同项合并、差异高亮 | 是：换对比对象 | 不跳页，原地重算 | chip 可取消选择 | 最多 3 块，超出不追加 |
| 种植记录查询 → 筛选 | 表格条数真的变化 | 是：按作物/阶段筛 | 不跳页，行号点进详情 | 「查看全部记录」清筛选 | 空结果给插画、真文案与清除入口 |
| 后台退款审核 → 提交 | 成功态写明结论已写回台账 | 是：管控动作落账 | 下一步到审计日志 | 统一侧栏可回总览 | 前台导航/页脚/站点地图 0 后台入口 |

## 四、业务口径（只写一份，不写死金额）

- **金额**：退款 = 已付 − 已作业（按公示价折算）− 平台服务费 2%；工单实结 = 公示价 − 结算服务费 1%；
  对账净额 = 应收 − 服务费 − 退款；农户可提现余额 = 全部资金流水逐笔相加。页面与 `api.js` 契约一致（接口金额单位分，展示 /100）。
- **状态**：退款四步（申请 → 平台核对 → 原路退回 → 到账）、提现四步（申请 → 平台复核 → 银行处理 → 到账）、
  工单六步主流程与一条退回分支保持不变；合同版本、活动版本都保留改前/改后/提交人/变更原因。
- **数据集**：新增 11 类（工单变更、退款、合同、合同版本、账单、对账、资金流水、提现、活动版本、调控记录、种植记录），
  全部由 `mock-data.js` 唯一一份数据源生成；`api.js` 新增 34 个带入参与返回类型的真实接口函数。
- **归属**：新页按角色挂到 4 个新业务流程组，全部进 `flowNav` 与站点地图；4 个后台页进统一侧栏，
  但**不进任何前台入口**；每页由统一 `put()` 注入本频道租金与价格公示。
- **双语**：33 页逐页独立撰写中英文案，英文不是中文翻译占位；子页返回按钮写明回到哪一级。

3. 线上部署与 `iarm.fun` 解析未由本方执行；按约定不主动查线上、不拿线上表现作验收依据。
4. 后台与前台在同一站点根，属逻辑隔离；`/admin/` 的 IP 白名单或 HTTP Basic 仍需运维在部署侧配置。
5. 模拟数据为前端静态数据，真实写入、审核回调、资金结算须接后端接口后才闭环；`api.js` 已给出全部契约。

## 七、本轮查出的真缺陷与误报登记

| 现象 | 判定 | 处理 |
|---|---|---|
| V2 分派写成 `return`，跳过 `init()` 后半段事件绑定，29 个新页表单走浏览器原生 GET、点击无反馈 | **真缺陷** | 改为渲染完成后继续绑定事件，复验全部表单成功态 |
| 资金流水支出金额大于收入，可提现余额为负，任何提现都被边界校验拦下 | **真缺陷（数据）** | 支出改为按收入比例发生，余额为正，提现 200 元可通过 |
| 后台 4 页没有前台流程导航条 | **探针口径误报** | 后台本就不注入 `flowNav`，抽检断言按目录区分，站点未改 |
| 静态断言按单引号取样 FLOW_GROUPS，新组用了双引号 | **断言口径误报** | 新组文件名统一单引号，闭环覆盖率恢复 0 未覆盖 |
| 静态断言写死 131 页 / 专家 hero 10 页 / `back.[a-z]+` | **断言口径随页面数刷新** | 数字改 164 / 16，专家新页返回键改全小写 `back.experts` |
| 提现错误提示用 toast 而非 `.sf-err` 元素 | **断言口径误报** | 验收按 toast 真实文案取样，没有改功能迁就断言 |
