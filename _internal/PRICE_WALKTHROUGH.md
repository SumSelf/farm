## 二、核查结论：原来为什么不算「挂钩」

原站各页确实散着金额字段——`farms.price`、`activities.price`、`produces.price`、
`workorders.price`、`dispatches.price`、`orders.amount`——但它们只是卡片上的一个数字：

- 没有统一的公示口径，同一笔钱在列表页、详情页、结算页各说各话；
- 田块只写「元/亩/季」单价，没有面积 × 单价 × 季数的租金计算，也没有押金与服务费；
- 没有「公示有效期 / 调价历史 / 计价规则」，用户无法回答「为什么是这个数」；
- 论坛、专家、个人、接单、后台等节点完全查不到与自己相关的价目；
- 没有价格公示频道，也没有后台的价目发布与调价审批。

结论：**不是缺几个按钮，是缺一份贯穿全站的价格公示总账与挂接机制**。属业务逻辑真缺陷。

## 三、唯一价格公示总账 `PRICE_BOOK`

放在 `assets/js/mock-data.js`，全站只写这一份；页面、`api.js` 回落、后台管控都从它取数。

| 数据集 | 条数 | 主要字段 |
|---|---:|---|
| `PRICE_CATS` 公示类目 | **9** | key / zh / en / unit / basisZh / basisEn |
| `PRICE_ITEMS` 公示价目 | **38** | cat / id / zh / en / price / unit / scopeZh / scopeEn |
| `PRICE_RULES` 公示规则 | **6** | zh / en（真答案，非翻译占位） |
| `PRICE_CHANGES` 调价公示历史 | **8** | id / at / itemZh / itemEn / before / after / unit / reasonZh / reasonEn / days |
| `PRICE_LEASE_FACTORS` 承包类型系数 | **5** | id / zh / en / factor |
| `farms` 田块租金（推导） | **24** | 由 `price × areaMu` 动态算出一季租金、押金 30%、服务费 2%、首期应付 |
| `PRICE_CHANNEL_CATS` 节点→类目映射 | **11** 档 | home / farms / activity / produce / dispatch / experts / forum / account / public / pricebook / admin |

九个类目逐个列全，不写「等等」：田块承包租金、场地租赁、活动报名、农产品、农事工单服务、
专家技术指导、配送与回收、押金与保证金、平台服务费与结算。

**频道职责边界**：价格公示频道只放「公示、查询、试算、规则、调价历史、后台发布」；
具体下单 / 报名 / 发工单仍归各自原频道，价格页只给直达链接，不重复实现交易流程。
论坛里的田园讨论、专家的技术文章仍归论坛 / 专家频道，价格页只取它们涉及的公示价目，不搬运正文。

## 四、全站挂接：每个节点都能看到自己的租金与价格

统一 `priceStrip()` 由唯一 `put()` 注入 **全部 131 页**（含首页、404、登录、后台、兜底页）：

| 页型 | 挂接内容 | 默认状态 |
|---|---|---|
| 前台业务页（田园 / 活动 / 农产品 / 接单 / 专家 / 论坛 / 个人 / 五角色业务节点） | 本频道关联类目 + 公示条目数 + 田块租金区间 + 公示版本与有效期 + 完整价目表 + 6 条规则 + 5 个业务入口 | 折叠成一行摘要，一键展开 |
| 详情页（`?id=`） | 额外「本单价格构成」：按记录 id 动态算单价 × 面积 × 季数、押金、服务费、首期应付 | 随展开一起出现 |
| 公共页 / 首页 / 兜底页 | 全站公示摘要 + 全类目价目表 + 直达入口 | 折叠 |
| 后台 17 页 | 全类目素价目管控表 + 后台价格管理入口 | 折叠，纯素不掺田园装饰 |

节点 → 关联类目（映射只写一份）：

```
田园档案  → 田块承包租金 / 押金 / 平台服务费
活动场地  → 场地租赁 / 活动报名 / 押金
农产品    → 农产品 / 配送与回收 / 平台服务费
接单工单  → 农事工单服务 / 专家技术指导 / 平台服务费

个人订单  → 田块租金 / 场地 / 农产品 / 工单 / 服务费（历史消费全口径）
首页      → 租金 / 场地 / 农产品 / 工单 / 专家（全站摘要）
```

**容器类名隔离（硬性要求）**：新增组件一律 `.sf-pub-*` 前缀，不复用卡片里原有的
`<span class="sf-price">`；原价格标签规则 `.sf-price{color:var(--sf-danger)...}` 保留。
首版曾复用同名类，浏览器实测把首页 16 个价格标签全染成区块底色，已作为真缺陷修复并加静态断言。

## 八、真实接口（前后端彻底分离）

`api.js` 新增 8 个方法，注明请求参数、返回类型与约定；`USE_MOCK=true` 时由同一份
`PRICE_BOOK` 组装响应，置 `false` 即走 `fetch`。金额一律分，面积亩，试算不落库，
发布进多级审核队列、不直接生效。

```
GET  /prices                    → PriceBook { version, period, cats[], items[], rules[], changes[], stats }
GET  /prices/items              → Paginated<PriceItem>   (cat / channel / status / page / pageSize / q)
GET  /prices/plots              → Paginated<PlotRent>    (farmId, plotNo, areaMu, rateCents, seasonCents, depositCents, feeCents, totalCents)
GET  /prices/breakdown          → PriceBreakdown         (?ds=&id=，lines[] + totalCents)
POST /prices/calc               → PriceBreakdown         ({ farmId, areaMu, seasons, leaseType }，不创建订单)
GET  /prices/changes            → Paginated<PriceChange> (beforeCents / afterCents / effectiveAt / noticeDays)
POST /admin/prices/publish      → { version, status:'pending_review', auditId }
GET  /admin/prices/audit        → Paginated<PricePublishTask>
```
